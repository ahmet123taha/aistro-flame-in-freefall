## Graph origin and provenance

Generated plots are reconstructed offline from reviewed source-table observations; documented graphs point to supported original image files. Filtering distinguishes these origins. Generated plot provenance binds source-file ID/name/SHA256, sheet, row/cell, raw values and declared axis units. Exact observations, input order and null gaps are preserved without resampling, fitting or interpolation. A generated plot is not an original source figure or a new measurement. The reader rejects invalid/mixed-unit or oversized input instead of silently downsampling; it supports at most 100000 points/separators. Unavailable source values stay unavailable. No language-model request, file upload or model training is used to prepare or filter these graphs.

Initial source-table coverage is limited to 13 Saffire I/II/III calibrated-sensor workbooks with named time and reviewed units, with 17 reviewed quantities per workbook except one with 13 accepted quantities. The documented-image review covers 24 Saffire III JPEG graphs and retains the three existing BASS image crops. The two prior equation-generated plots remain explicitly labelled as such. The preparation snapshot reports 217 source-table plots with 3,750,100 points (83,591,481 compressed add-on bytes); with the two prior equation curves the generated filter totals 219, and documented sources total 27. The four radiometer channels in one workbook are excluded because their units were not reviewed. The pinned graph-manifest SHA256 is 22904f417b28bb778a10e289cab3a2c3324aa92facf96a760a31ab92ce5f73ec. Preparation/source-hash readback does not establish that every dataset table or paper is fully validated.

The prepared graph index/data in Prepared_Graphs/v1 are an optional additive dataset add-on. Baseline and data SHA256, source identity and bounded decompression are checked before use; original NASA files/catalog are not rewritten. Missing/invalid add-on state is reported explicitly. Supporting documented image formats are PNG/JPEG/WebP; this does not claim automatic extraction of every PDF graph or unreadable binary source.

## Current-turn dialogue conditions

A bounded application parser reads only the latest actual question before retrieval, analyzer context and scoring. Environment/greeting paths do not extract new measurements, and source quotations or previous history are not treated as new user readings. Explicit supported TR/EN material and numerical expressions can update the existing condition state with an exact quote, user_reported/estimated basis, original value/unit and conversion receipt.

Supported unit families include temperature C/F/K; gravity g or m/s²; pressure Pa/kPa/bar/atm; oxygen percentage; flow cm/s or m/s; and thickness mm/cm. A newer explicit value replaces the corresponding earlier field, and a supported explicit clear removes it. Missing, unknown, ambiguous, range, hypothetical or source-quoted values preserve existing conditions rather than silently supplying a number. Quoted/reported-source turns are conservatively skipped wholesale; unsupported units, comparisons, hypothetical values and conflicts are not automatically filled. Unsupported natural-language/model proposals remain manually reviewed; this is a bounded grammar, not unrestricted understanding of arbitrary technical prose.

The UI applies the same-request canonical result without moving focus/scroll, opening optional panes or issuing a second API call. It preserves the ranking computed for those conditions. On a provider failure, explicit user conditions can remain applied while no failed/incomplete model answer is presented as a scientific result. Scientific scoring, source provenance and condition validators remain authoritative; a parser receipt is user-provided context, not a sensor measurement or proof of scientific applicability.
